# Client backend logging audit

Reviewed non-UI client code in App, AI, Agent, Models, Storage, Web navigation, downloads, extensions, content blocking, favicons, website apps, and updater targets.

The shared `BrowserLog` path now formats nested `NSError` chains, includes Codable coding paths, includes source locations in release output, and records safe Foundation failure reasons, failing URLs and file paths through the existing privacy helpers. Decoding context underlying errors are retained. Release output omits arbitrary messages and dynamic coding keys; debug messages redact credentials. URLs, local paths, identifiers, arbitrary values, request bodies, credentials, cookies, and authorization values remain redacted by the existing helpers.

The default policy emits warning, error, and fault events. Trace, debug, info, and notice events remain available with `ASTRA_LOG_VERBOSE=1` or `ASTRA_PERFORMANCE_BENCHMARK=1`. Disabled calls return before evaluating autoclosure messages or metadata. Routine timing events are also opt-in; verbose runs still promote slow operations to warnings. Main-thread stall faults remain enabled by default.

Failure coverage was added at restoration keychain and AES-GCM boundaries, sync settings and session loading, installer response writing, updater startup, agent listener/request/tool handling, website monitoring mutations and notifications, favicon persistence/fetch failures, search suggestion transport failures, web push authorization/delivery, AI page extraction, website-app rollback paths, browser hydration and persistence writes, startup window-record restoration, AI chat history, CLI process input, usage-limit transport/status/decode failures, download deletion/rename/segment assembly/index persistence, profile import warnings, extension preparation, website-app menu installation, and data export. HTTP terminal failures include method, status when available, response bytes, server request ID, and elapsed time. Expected cancellation, optional cache misses, favicon 404s, and bounded probe failures remain quiet. Existing subsystem-specific logs cover network retries, persistence saves, downloads, web navigation, AI requests, extensions, content blocking, and favicon work.

Intentional skips include `try?` used for task cancellation sleeps, optional browser probes, temporary-file cleanup after a primary failure, and JavaScript iframe traversal where failure only means that frame is inaccessible. This is source-level coverage, not a runtime fault-injection audit. OSLog delivery and privacy rendering require the macOS app target; the focused check validates formatter output, lazy autoclosures, nested errors, and the quiet policy.

The startup benchmark explicitly opts into verbose logging. Normal app launches and the AI usage file omit routine success/cancellation events. Timings are available in explicit verbose runs. Private server request UUIDs are validated before being recorded publicly for client/server correlation.

The registry reader now reports corrupt/oversized/invalid records while treating absent files as normal. Search provider HTTP and malformed-response failures, download-folder bookmark failures, and failed website-app rollback/registration paths retain their root causes. Session keychain errors expose the actual OSStatus through NSError bridging.

Verification completed: Xcode MCP app build (including installer/updater dependencies), formatter/privacy/lazy-evaluation checks in debug and release with quiet and verbose policies, startup benchmark self-tests, workflow report checks, website-app bundle self-tests, checkpoint/privacy cache checks, and window-record sidecar checks. The existing download-recovery source guard fails at HEAD because it expects `await self.checkForStalls(threshold: 90)` while the source uses `await checkForStalls(threshold: 90)`; its behavior and assertion were left unchanged.

Focused formatter check command: `swiftc astra/App/BrowserLog.swift astra/Storage/BrowserSessionStore.swift checks/browser-log-check.swift -o /tmp/astra-log-check && /tmp/astra-log-check`. Compile with `-D DEBUG` for debug privacy behavior; rerun with `ASTRA_LOG_VERBOSE=1` and `ASTRA_PERFORMANCE_BENCHMARK=1` to check the opt-in policy.
